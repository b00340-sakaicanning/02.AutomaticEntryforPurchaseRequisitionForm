# 05 セットアップ手順

- 版: v1.0（2026/10/31）
- 対象: このアプリを GAS に反映して動かす人（オーナーのアカウントで作業する）
- clasp は使わない。`gas_app/` のファイルを GAS エディタにコピペする（K-45）。

---

## 0. まず画面を見る（GAS 不要）
1. プロジェクト直下の `local_preview.html` をブラウザ（Chrome / Edge）で開く。
   - 架空のデータで、本物の `Code.gs` がブラウザの中で動く。
   - 暗証番号はすべて `123456`。上部のバナーで操作者（入力者・承認者・管理者・経理）を切り替えられる。
   - データはそのブラウザに保存される。「データ初期化」で最初の状態に戻る。
   - CSV は Shift_JIS で出力される（ブラウザ内の変換。正式な確認は GAS で行う）。
2. 画面を直したら、`node tools/build_local_preview.js` で作り直す（Node.js LTS が必要）。

**試してほしい操作の例**
| # | 操作者 | 操作 |
|---|--------|------|
| 1 | 入力者（山田） | 新規入力 → 承認依頼 |
| 2 | 承認者（佐藤） | 入力データ一覧の「承認」→ 暗証番号 123456 |
| 3 | 経理（田中） | 承認済一覧で「資材」→ 候補を選んで確定 → 「コード」で補完 → CSV出力 → 反映済にする |
| 4 | 管理者（高橋） | システム反映済一覧で「承認済に戻す」、マスタ管理タブ |
| 5 | 承認者（佐藤） | 差し戻し（理由を入力）→ 入力者で修正して再依頼 |

## 1. 開発環境を作る
### 1.1 スプレッドシートとスクリプト
1. Google ドライブで新しいスプレッドシートを作り、名前を **`物品購入届DB_開発`** にする（名前に「開発」が入っていると、ドライブのフォルダが `物品購入届_開発` になる）。
2. メニュー「拡張機能」→「Apps Script」を開く。
3. 次の表のとおりファイルを作り、`gas_app/` の中身を**丸ごと**貼り付けて保存する（Ctrl+S / Cmd+S）。

| GAS エディタのファイル | 作り方 | 貼る原本 |
|----------------------|--------|---------|
| `コード.gs` | 名前を `Code` に変える | `gas_app/Code.gs` |
| `index.html` | 「＋」→「HTML」→ `index` | `gas_app/index.html` |
| `css.html` | 「＋」→「HTML」→ `css` | `gas_app/css.html` |
| `js.html` | 「＋」→「HTML」→ `js` | `gas_app/js.html` |
| `Tests.gs` | 「＋」→「スクリプト」→ `Tests` | `gas_app/Tests.gs`（開発環境だけ） |
| `appsscript.json` | 「プロジェクトの設定」（歯車）→「『appsscript.json』マニフェスト ファイルをエディタで表示する」をオン | `gas_app/appsscript.json` |

### 1.2 初期セットアップ
1. スプレッドシートを再読み込みすると、メニューに「物品購入届」が出る。
2. 「物品購入届」→「初期セットアップ」を実行する。
   - 初回は権限の承認を求められる。「権限を確認」→ アカウントを選ぶ →「詳細」→「（プロジェクト名）に移動」→「許可」。
   - 12のシートと設定、ドライブのフォルダ（`物品購入届_開発/添付書類・マスタ取込・バックアップ`）ができる。
   - 何度実行しても同じ結果になる（既存の設定は上書きしない）。

### 1.3 マスタの取込
1. ドライブの `物品購入届_開発/マスタ取込/` に、`reference/各種マスタ/` の次の3つをアップロードする。
   - `資材マスター.csv`、`取引先マスター.csv`、`365User.csv`
   - CSVのままアップロードする。ドライブの設定「アップロードしたファイルを Google ドキュメント エディタ形式に変換する」がオンだとスプレッドシートに変わってしまうので、オフにしておく。
2. 「物品購入届」→「マスタ取込」→「すべて」を実行する。
   - 期待する件数: 資材 4823、発注先 885、社員 83、部署 21、種別 73（「部署・種別」の行に合計が出る）。
   - 件数が違う・文字化けがある場合は、その内容を連絡する（CP932 の読み込みは GAS 上で未確認。docs/04 §0）。

### 1.4 開発用サンプルデータ（K-48）
1. 「物品購入届」→「開発: サンプルデータ投入」を実行する。次を仮の値で設定する。
   - 部署・種別の有効化、承認者対応表（課長・課長代理）、納入先（社名に「サカイキャニング」を含む取引先）、管理者・経理（コーポレート部門の社員から自動。`Tests.gs` 先頭の `SEED_ADMIN_IDS` などで指定可）
   - 承認者・管理者・経理の暗証番号をすべて `123456` にする
   - 各ステータスのサンプル届出を6件作る
2. 終わったら、ダイアログに管理者・経理・入力者の名前が出る。この人を操作者に選んで試す。

### 1.5 テスト
1. 「物品購入届」→「開発: テストを実行」を実行する。
2. 結果のダイアログで NG が0件であることを確認する。詳細は Apps Script の「実行数」でログを見る。
   - TC-MI-01（件数）、TC-CSV-02（Shift_JIS）、TC-AU-01（ロック）などは GAS 上でしか確かめられない。

### 1.6 画面で試す（テストデプロイ）
1. Apps Script で「デプロイ」→「デプロイをテスト」→ 種類「ウェブアプリ」→ URL（末尾 `/dev`）を開く。
   - テストデプロイは、スクリプトの編集者だけが開ける。コードを貼り替えて保存すれば、すぐに反映される。
2. 「0. まず画面を見る」の表の操作を試す。CSVは Shift_JIS で出力されるので、Excel で開いて文字化けしないことを確認する。

## 2. コードを直したとき（貼り替え）
1. 変更されたファイル（実装AIの完了報告に「貼り替えが必要なファイル」として書かれる）を、GAS エディタで丸ごと貼り替えて保存する。
2. 開発環境はテストデプロイの URL を再読み込みすれば反映される。
3. 本番は「デプロイ」→「デプロイを管理」→ 鉛筆アイコン →「バージョン: 新バージョン」→「デプロイ」。URL は変わらない。

---

## 3. 本番環境を作る（フェーズ12の後。ユーザーの指示があってから）
1. スプレッドシート **`物品購入届DB`** を作り、1.1 の手順で `Code.gs`・`index`・`css`・`js`・`appsscript.json` を貼る（**`Tests.gs` は貼らない**）。
2. 「初期セットアップ」→ ドライブ `物品購入届/マスタ取込/` にCSVを置く →「マスタ取込 > すべて」。
3. シートを手で設定する（サンプルデータ投入は使わない）。
   - 部署マスタ・種別マスタ: 対象の行の「有効」を TRUE、必要なら「共通部署コード」を入れる（U-02、U-03、Q-02）
   - 納入先マスタ: 自社拠点を登録（Q-03）
   - 承認者対応表: 部署ごとの承認者と優先順（Q-04）
   - 権限マスタ: 管理者・経理（U-09）
4. 「暗証番号を発行」で、承認者・管理者・経理に暗証番号を発行し、本人に伝える。
5. 「バックアップトリガーを設定」を実行する。
6. 「デプロイ」→「新しいデプロイ」→「ウェブアプリ」。次のユーザーとして実行「自分」、アクセスできるユーザー「全員」（使えなければ組織内。Q-01）→ URL を社内だけに配布する。

## 4. 運用
| 作業 | 頻度 | 担当 | 方法 |
|------|------|------|------|
| マスタの更新（資材・取引先・社員） | 月1回（仮。U-04） | 管理者 | CSVを「マスタ取込」フォルダに置き、マスタ管理タブまたはメニューで取り込む |
| 承認者対応表の見直し | 人事異動のとき | 管理者 | シートを直接編集 →「キャッシュをクリア」 |
| 暗証番号の発行・再発行 | 随時 | 管理者 | マスタ管理タブ、またはメニュー「暗証番号を発行」 |
| CSV出力と反映済への切替 | 随時 | 経理 | 承認済一覧 |
| バックアップの確認 | 月1回 | 管理者 | ドライブ `物品購入届/バックアップ/` |
| 古いデータの整理 | 年1回 | 管理者 | 初版は機能なし（K-30）。反映済で保持期間（U-06）を過ぎた行を、バックアップを取ってから別のスプレッドシートへ移す |

- マスタのシートを直接編集したら、メニュー「キャッシュをクリア」を実行する（最大6時間、古い内容が画面に出るため）。

## 5. 未決事項を決めたときに変える場所
| ID | 変える場所 |
|----|-----------|
| U-01 | 設定 `SUPPLIER_VISIBLE_ACCOUNTS`（新しく取り込む行に効く）／発注先マスタの「表示」列 |
| U-02・U-03 | 種別マスタ・部署マスタの「有効」列 |
| U-05 | 設定 `ATTACHMENT_ALLOWED_EXT`・`ATTACHMENT_MAX_MB` |
| U-10 | 設定 `CSV_COLUMNS`・`CSV_HEADER_NAMES`・`CSV_HEADER`・`CSV_DATE_FORMAT`・`CSV_CHARSET`・`CSV_DELIMITER`・`CSV_LINE_ENDING`・`CSV_QUOTE_MODE`・`CSV_FILENAME_PATTERN` |
| U-11 | 設定 `QUANTITY_DECIMALS` |
| K-13 | 設定 `PIN_LENGTH`・`PIN_SESSION_MINUTES`・`PIN_MAX_FAILS`・`PIN_LOCK_MINUTES` |
| K-47 | 設定 `STATUS_COLORS` |

- 設定シートを変えたら、画面を再読み込みすれば反映される（設定はキャッシュしていない）。
- コードの変更が必要なもの（U-08 など）は、`plan/09_プロンプト修正ガイド.md` §3 の影響箇所マップに従って依頼する。

## 6. ローカルでの検証（開発者向け）
| コマンド | 内容 |
|---------|------|
| `node tools/run_tests_node.js` | フェイクの上で、pure テスト＋マスタ取込（reference のCSV）＋サンプルデータ＋結合テストを実行する |
| `node tools/run_tests_node.js --pure` | pure テストだけ |
| `node tools/build_local_preview.js` | local_preview.html を作り直す |

- フェイクで確かめられないこと: GAS 上の Shift_JIS 変換、CP932 の読み込み、ドライブの権限、ロックの競合、トリガー。開発環境で確認する。
