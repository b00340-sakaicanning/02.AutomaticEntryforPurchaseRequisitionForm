## 1. 全体構成
```
[ブラウザ] ──URL（社内配布・ログインなし）──▶ [GAS ウェブアプリ（コンテナバインド・実行ユーザー=オーナー）]
                                                 ├─ スプレッドシート「物品購入届DB」（12シート）
                                                 ├─ ドライブ「物品購入届/」（添付書類・マスタ取込・バックアップ）
                                                 ├─ CacheService（マスタ・認証トークン）
                                                 ├─ LockService（更新の直列化）
                                                 └─ 時間主導トリガー（毎月のバックアップ）
[管理者] スプレッドシートを直接編集 ＋ メニュー「物品購入届」
[経理]   CSVを出力 → 販売管理システムへ手作業で取込
```

## 3. 画面構成
| タブ | 主な機能 | 表示する人 |
|------|---------|-----------|
| 新規入力 | 新規入力と修正モード（一覧の「修正」から開く） | 全員 |
| 入力データ一覧 | 全ステータスの一覧、フィルタ、行ボタン（詳細・修正・承認依頼・承認依頼取消・承認・差し戻し・削除） | 全員 |
| 承認済一覧 | 資材の確定、コード補完、CSV出力、反映済にする | 全員（操作は経理・管理者） |
| システム反映済一覧 | 閲覧、CSV再出力、承認済に戻す | 全員（操作は経理・管理者） |
| マスタ管理 | マスタ取込、暗証番号の発行、設定の閲覧 | 管理者だけ（開くときに暗証番号） |

- ダイアログ: 詳細、差し戻し理由、資材の確定、コード補完、暗証番号、添付のプレビュー、確認
- デザイン: CSS 変数・部品は参考アプリ「02.ロッカーキー貸出管理(Gemini)」と同じ（plan/05 §0）

## 4. 処理の流れ
```
入力者: 新規入力 → 一時保存／入力完了 → 承認依頼（提出日を記録）
承認者: 承認（資材候補を計算して仮設定） ／ 差し戻し（理由必須） ／ 承認依頼取消
経理:   資材を確定・コードを補完 → CSV出力（出力回数を記録） → 販売管理システムへ取込 → 反映済にする
管理者: 承認取消・承認済に戻す（救済）・マスタ管理
```

## 5. 通信と認証
- 画面からの呼び出しは `google.script.run` を Promise にした `api()` を通す。戻り値は `{ok, data}` / `{ok:false, error:{code, message, fields}}`。
- 第1引数は `ctx = {operatorId, token}`。操作者は自己申告で、承認者・管理者・経理の操作はトークン（暗証番号で取得。ScriptCache に30分）を毎回サーバーで検証する。
- エラー `AUTH_REQUIRED` を受けたら、画面が暗証番号ダイアログを出し、認証後に同じ操作をやり直す。
- CSV・添付は Base64 で受け渡す。
