## 1. 目的と範囲
- **背景**: 販売管理システムの外で物品を買うとき、紙の物品購入届を回覧し、経理担当者が販売管理システムへ手入力している。回覧・添付の管理・転記ミスが課題。
- **目的**
  - 物品購入届を GAS ウェブアプリで入力・添付・承認できるようにする。
  - 承認済みのデータから、販売管理システムへのインポート用CSV（Shift_JIS）を出力する。
- **対象**: 入力、一時保存、添付、承認依頼、承認、差し戻し、承認取消、一覧、フィルタ、CSV出力、反映済への切替、マスタ管理
- **対象外**: 販売管理システムへの取込作業（経理が手作業で行う）、自動連携（D-22）
- **前提**: 1届出＝1物品（D-03）。ログインはせず、操作者を選ぶ（D-01）。

## 2. 利用者と役割
| 役割 | 判定 | 暗証番号 |
|------|------|----------|
| 入力者 | 操作者がその届出の入力者 | 不要 |
| 承認者 | 操作者がその届出で**指定された承認者**（入力者本人は除く。K-01） | 必要 |
| 管理者 | 権限マスタで「管理者」 | 必要 |
| 経理担当 | 権限マスタで「経理」 | 必要 |

- 暗証番号は数字6桁。管理者がランダムに発行するか、番号を指定して設定する（指定する番号も同じ桁数。推測しやすい番号も可。本人による変更は無し）。認証は30分有効で、5回誤ると15分ロックする（K-13。値は設定で変更可）。
- 操作の権限は、`docs/04_実装仕様.md` 第1部 §3.2 の権限マトリクスのとおり。

## 3. 機能要件
| 機能 | 内容 | 詳細 |
|------|------|------|
| 新規入力・修正 | 部門・種別・承認者・発注先（マスタ／手入力／指定なし）・納入先（同）・購入物品名・型番・数量・単位補足・理由・納品日・添付2点 | docs/04 第1部 §4、plan/05 §3 |
| ステータス | 一時保存 → 入力完了 → 承認依頼中 → 承認済 → システム反映済。差し戻し・取消あり | docs/04 第1部 §1〜§2 |
| 入力データ一覧 | 全ステータスを色分けで表示。フィルタ・クイックフィルタ・並び替え・行ボタン | plan/05 §4 |
| 承認済一覧 | 資材コードの確定、取引先コードの補完、CSV出力、反映済にする | plan/05 §5.1 |
| システム反映済一覧 | 閲覧、CSV再出力、承認済に戻す（管理者） | plan/05 §5.2 |
| 資材コードの候補 | 承認時に4段階の優先順で候補を出し、先頭を仮設定。経理が確定する（D-02、K-10） | docs/04 第1部 §6 |
| CSV出力 | 発注先コード・納入先コード・資材コード・入数・数量・納期（仮仕様。設定で変更可。D-10） | docs/04 第1部 §7 |
| マスタ管理 | マスタ取込、暗証番号の発行、設定の閲覧（それ以外の編集はシートで直接行う。K-14） | plan/05 §7 |
| 通知 | 初版は送らない。拡張点だけ用意（D-11） | docs/04 第1部 §13 |

## 4. 非機能要件
| 区分 | 要件 |
|------|------|
| 排他制御 | LockService で直列化し、バージョンによる楽観ロックで先行する更新を検出する |
| 操作ログ | すべての保存・状態変更・CSV出力・取込・認証を記録する |
| 性能 | 一覧の表示は3秒以内を目安。マスタはキャッシュする |
| 添付 | ドライブの専用フォルダ（共有しない）。アプリ経由で表示・ダウンロード |
| セキュリティ | URL は社内だけで配布する。暗証番号はハッシュ化する |
| バックアップ | 毎月1日にスプレッドシートのコピーを作る |
| 利用環境 | PC（Chrome・Edge）。スマホは幅375pxで崩れないこと（K-33） |
| デザイン | 「02.ロッカーキー貸出管理(Gemini)」と同じテイスト（K-44） |
| 開発 | clasp を使わず、GAS エディタにコピペで反映する（K-45） |
