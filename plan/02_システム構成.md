## 1. 全体構成

```
[利用者のブラウザ（Chrome/Edge）]
   │  ウェブアプリのURL（社内だけで配布。Googleアカウントは不要）
   ▼
[GAS ウェブアプリ（コンテナバインド。実行ユーザー: オーナー）]
   │  HtmlService の SPA ⇄ google.script.run
   ├─▶ スプレッドシート「物品購入届DB」（届出データ・操作ログ・マスタ・設定・暗証番号）
   ├─▶ ドライブ「物品購入届/」（添付書類・マスタ取込・バックアップ。共有しない）
   ├─▶ CacheService（マスタのキャッシュ、認証トークン）
   ├─▶ LockService（更新の直列化）
   └─▶ 時間主導トリガー（毎月のバックアップ）

[管理者] スプレッドシートを直接編集する ＋ カスタムメニュー「物品購入届」
[経理]   CSVを出力する → 販売管理システムへ手作業で取り込む（対象外。D-22）
```

| 要素 | 内容 | 根拠 |
|------|------|------|
| フロントエンド | HtmlService の SPA。タブで切り替える。デザインは「02.ロッカーキー貸出管理(Gemini)」に合わせる（05 §0）。外部の読み込みは Google Fonts だけにする | 要 L36、K-44 |
| バックエンド | Google Apps Script（V8ランタイム） | 要 L37 |
| GAS の形態 | コンテナバインド（スプレッドシートに紐づける） | K-02 |
| データ | スプレッドシート（03 データ設計） | 要 L38 |
| 添付書類 | ドライブの専用フォルダ。届出IDごとにサブフォルダを作る | 要 L39 |
| 開発 | **clasp は使わない**。ローカルの `gas_app/` で書いたコードを、GAS エディタにコピペして反映する | K-45（要 L41 を変更） |

### 2.1 Code.gs のセクション構成
- `Code.gs` は1ファイルにまとめ、次の順にセクションを並べる。本書で【Auth】のように書いたものは、このセクションを指す。
- 各セクションの先頭には、次の形の見出しコメントを入れる。エディタの検索（Ctrl+F／Cmd+F）で `【Auth】` と探せば、そのセクションに飛べるようにする。
  ```js
  // =====================================================================
  // 【Auth】 暗証番号・トークン・役割の判定
  // =====================================================================
  ```

| 順 | セクション | 内容 |
|----|-----------|------|
| 1 | 【Api】 | `doGet`、`include`、`handle_`、画面から呼ぶ公開関数のすべて（本書で「Code.gs に置く」と書いた関数） |
| 2 | 【Config】 | シート名・列の対応・ステータス・操作・設定の既定値・`getSetting` |
| 3 | 【Utils】 | `AppError`、日付、文字の正規化、キャッシュの分割 |
| 4 | 【Repository】 | シートの読み書き、ロック、採番、ログ、マスタのキャッシュ |
| 5 | 【Auth】 | 暗証番号、トークン、役割の判定 |
| 6 | 【Validator】 | 入力チェック |
| 7 | 【Workflow】 | 権限表・遷移表、保存、状態変更、コード補完 |
| 8 | 【MaterialMatcher】 | 資材候補の選定・確定・検索 |
| 9 | 【CsvExport】 | CSVの生成と出力の記録 |
| 10 | 【MasterImport】 | マスタの取込と、部署・種別の生成 |
| 11 | 【Attachment】 | 添付の保存・差し替え・取得 |
| 12 | 【Notifier】 | 通知（初版は何もしない） |
| 13 | 【Menu】 | `onOpen`、カスタムメニュー、初期セットアップ、バックアップ |

**1ファイルにまとめるための規則**
- GAS では、すべての .gs ファイルが同じ名前空間を共有する。関数名・定数名がセクションの間で重ならないようにする。
  - 内部用の関数は、末尾に `_` を付ける（GAS のエディタの実行メニューにも出なくなる）。
- `Code.gs` の先頭に、版とセクションの目次をコメントで書く（例: `// 版: v1.0 2026/11/xx`）。貼り付けた版を、GAS エディタ上で確かめられるようにする。
- `Tests.gs` は `Code.gs` の関数を呼ぶだけにする。`Code.gs` からは `Tests.gs` の関数を呼ばない。そのため、本番に `Tests.gs` が無くても動く。

## 3. appsscript.json の方針

```json
{
  "timeZone": "Asia/Tokyo",
  "runtimeVersion": "V8",
  "exceptionLogging": "STACKDRIVER",
  "webapp": { "executeAs": "USER_DEPLOYING", "access": "ANYONE_ANONYMOUS" },
  "oauthScopes": [
    "https://www.googleapis.com/auth/spreadsheets.currentonly",
    "https://www.googleapis.com/auth/drive",
    "https://www.googleapis.com/auth/script.scriptapp",
    "https://www.googleapis.com/auth/script.container.ui"
  ]
}
```
- **`access`**: Workspace のポリシーで匿名アクセスが使えなければ `DOMAIN` にする（K-18、Q-01）。
- **`drive` スコープ**: フォルダの作成、ゴミ箱への移動、バックアップのコピーに要る。
- **`script.scriptapp` スコープ**: トリガーの登録に要る。
- **将来メール通知を有効にするとき**: `https://www.googleapis.com/auth/script.send_mail` を足し、権限を承認し直す（04 §13）。
- スコープが足りずにエラーになったら、追加して `docs/02` に記録する。
- **反映方法**（clasp を使わないため）
  1. GAS エディタの「プロジェクトの設定」で「『appsscript.json』マニフェスト ファイルをエディタで表示する」をオンにする。
  2. エディタに表示された `appsscript.json` に、`gas_app/appsscript.json` の中身を貼る。

### 3.1 コードの反映手順（コピペ。K-45）
| GAS エディタのファイル | 作り方 | 貼る原本 | 本番 | 開発 |
|----------------------|--------|---------|:---:|:---:|
| `コード.gs`（初期のファイル） | 名前を `Code` に変える | `gas_app/Code.gs` | ○ | ○ |
| `index.html` | 「＋」→「HTML」で `index` | `gas_app/index.html` | ○ | ○ |
| `css.html` | 「＋」→「HTML」で `css` | `gas_app/css.html` | ○ | ○ |
| `js.html` | 「＋」→「HTML」で `js` | `gas_app/js.html` | ○ | ○ |
| `Tests.gs` | 「＋」→「スクリプト」で `Tests` | `gas_app/Tests.gs` | × | ○ |
| `appsscript.json` | §3 の手順で表示 | `gas_app/appsscript.json` | ○ | ○ |

- 貼るときは、ファイルの中身を全選択して丸ごと置き換える（部分的に貼り替えない）。
- 実装AIは、1つのフェーズで変更したファイルを、完了報告に「貼り替えが必要なファイル」として列挙する（README §2.2）。
- 貼り付けと保存（Ctrl+S／Cmd+S）はユーザーが行う。

## 5. クライアントとサーバーの通信（K-16、K-17）

| 処理 | 方式 |
|------|------|
| 通常のAPI | `google.script.run.withSuccessHandler().withFailureHandler().関数名(ctx, ...)` を、`api()` で Promise にして使う |
| 初期データ | 起動時に `getInitData()` を1回呼び、マスタ（社員・部署・種別・承認者・発注先・納入先）を画面に持つ |
| 一覧 | タブを開くたびに `getRequestList()` を呼ぶ。絞り込みは画面の中で行う |
| CSV | サーバーが Base64 を返し、画面で `Uint8Array` に戻して `Blob` を作り、`a[download]` で保存する |
| 添付のアップロード | 画面の `FileReader.readAsDataURL` で Base64 にし、1ファイルずつ `uploadAttachment()` で送る（10MB以下） |
| 添付の表示 | `getAttachment()` で Base64 を受け取り、Blob URL にして新しいタブで開く。Excel はダウンロードする |

- `google.script.run` では `Date` 型を渡さない。文字列で渡す。

## 6. 認証とセッション（K-13、K-37）
- **前提**
  - 実行ユーザーが「自分」で匿名アクセスなので、サーバーは利用者が誰かを判別できない。
  - そのため、画面から送られる `operatorId` を「自己申告の操作者」として扱う。
- **入力者としての操作**: 暗証番号なしで行える（なりすましは防げない。要 L59）。操作ログで追跡する。
- **承認者・管理者・経理としての操作**
  - 暗証番号の認証で得たトークンを、毎回サーバーで検証する。
  - トークンは ScriptCache（最長6時間）に `auth:{token}` のキーで、有効期限30分として保存する。
  - 画面側は `sessionStorage` に持つ（ブラウザのタブを閉じると消える）。
- **暗証番号のハッシュ**: 暗証番号シート（保護・非表示）に保存する。平文はどこにも残さない。
- 処理の詳細は `04_業務ロジック仕様.md` §3.3〜3.4 のとおり。

## 7. デプロイと公開（構 L183-188、K-18）
1. 開発環境の GAS エディタに §3.1 の手順でコードを貼り、エディタで動作を確認する。
2. 「デプロイ」→「新しいデプロイ」→「ウェブアプリ」を選び、次のように設定する。
   - 次のユーザーとして実行: 自分
   - アクセスできるユーザー: 全員（使えなければ組織内）
3. 初回は権限を承認する。
4. 発行されたURLを、社内だけで配布する。
5. 更新するときは、コードを貼り替えて保存してから、「デプロイを管理」で同じデプロイの版を「新バージョン」に上げる。URLは変えない。
   - 貼り替えただけでは、公開中のウェブアプリには反映されない。動作確認には「テストデプロイ」（`/dev` のURL）を使う。
   - デプロイIDとスクリプトIDは機密として扱い、計画書やdocsには書かない。

## 10. 性能とキャッシュ（要 L322）
- **目標**: 一覧の表示は3秒以内（年間数千件まで）。
- **シートの読み込み**: 1回の API で、1つのシートを `getDataRange().getValues()` で1回だけ読む。
  - 1セルずつ読んだり書いたりしない。
  - 1行を更新するときは、その行の範囲に `setValues` を1回だけ行う。
- **マスタのキャッシュ**
  - `CacheService.getScriptCache()` に `MASTER_CACHE_SECONDS` 秒持つ。
  - 1つのキーには100KBまでしか入らないので、`chunkCachePut` で分けて保存する。
  - マスタ取込とキャッシュクリアのメニューで消す。
- **資材マスタ（約4800行）**: 画面には送らない。資材候補の計算と検索のときだけ、サーバー側で読む。
- **データが増えたとき**（要 L327、K-30）: 初版では対応しない。一覧が遅くなったら、反映済の古い行を別のシートに移す機能を追加する。
