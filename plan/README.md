# 物品購入届CSV出力アプリ 詳細実装計画（plan/）

- 版: v1.1（2026/10/31。デザインとコピペ反映の方針を追加）
- 元資料: `plan_draft/` の要件定義・構築手順（ドラフト v0.1）
- 読み手: このアプリを実装する AI（Claude Code または Gemini）と、その指示者

## アプリの概要
- 紙の物品購入届を、GAS ウェブアプリで入力・添付・承認できるようにする。
- 承認済みのデータから、販売管理システムへのインポート用CSV（Shift_JIS）を出力する。
- 構成:
  - 画面: HtmlService の SPA
  - データ: スプレッドシート
  - 添付: ドライブ
  - 開発: clasp は使わない。`gas_app/` の原本（Code.gs / index.html / css.html / js.html の4ファイル＋開発用の Tests.gs）を GAS エディタにコピペする（K-45、K-46）
  - デザイン: 「02.ロッカーキー貸出管理(Gemini)」と同じテイスト（K-44。05 §0）
- 利用者: ログインはしない。画面で操作者を選び、承認者・管理者・経理として操作するときは暗証番号を入力する。

## 2. 実装AIへの作業ルール

### 2.1 プロジェクトのルール（CLAUDE.md / GEMINI.md）
- やり取り、コメント、ドキュメントは日本語にする。
- コードを変更する前に、変更内容と理由を説明し、確認を得る。
- 調査はファイルを丸ごと読まず、grep などで該当箇所を絞って確認する。
- ファイルやフォルダを削除するときは、ゴミ箱へ移す。
- 修正は必要最小限の差分にとどめる。
- `.env`、`.clasprc.json`、`.clasp.json`、`secrets/` は読まない（参考アプリのフォルダを見るときも同じ）。
- **修正したら、次を行う。**
  - 修正したファイルの一覧を示す。
  - `history/YYYYMMDDhhmm_変更内容.md` を作る。
- **画面の確認**
  - スクリーンショットや確認用の html は `screenshot/` に置く。
  - 完了報告の前に、`screenshot/YYYYMMDDhhmm_変更内容/`（history と同じ名前）に移す。
- **画面の見た目や表示内容を変えたら、`local_preview.html` を作り直す**（`node tools/build_local_preview.js`）。
- 命名: 関数名・変数名はキャメルケース、クラス名はパスカルケースにする。
- GAS のコードは `gas_app/` に置く。

### 2.2 この計画に固有のルール
1. **仕様の正**
   - フェーズ0より後は `docs/` を正とする。
   - docs に無いこと、または docs と plan が食い違うことは、plan で確認し、ユーザーに報告する（K-36）。
2. **確定事項（D-xx）は勝手に変えない**
   - 仮決め（K-xx）を変えたほうがよいと判断したら、理由を添えてユーザーに提案する。
   - 承認を得たら、`09_プロンプト修正ガイド.md` §3 のとおりに直す。
3. **フェーズの進め方**
   - フェーズは順番に進める。
   - 完了条件とテストの結果を報告し、ユーザーの確認を得てから次へ進む。
4. **タスクの記録**
   - 終わったタスクは、`07_タスク一覧.md` のチェックボックスを `[x]` にする。
   - history には、フェーズ名、実施したタスク、テストの結果の表（テストID・OK/NG）を書く。
5. **権限と遷移の判定はサーバー側で必ず行う**。画面の判定は補助にすぎない（04 冒頭）。
6. **ID の採番やファイルIDなどの環境に依存する値をコードに書き込まない**。値は設定シートに置く（02 §4）。
7. **本番環境への push とデプロイは、ユーザーの明示的な指示があるまで行わない**（K-42、T12-5）。
8. **ユーザーが手元で行う作業は、手順を示して依頼する**。
   - 対象: GAS エディタへのコードの貼り付けと保存、Apps Script の権限承認、マスタCSVのアップロード、デプロイなど。
   - AI が代わりに行ったと報告しない。
9. **コードはコピペで反映する前提で書く**（K-45）。
   - サーバー処理は `Code.gs` の1ファイルにまとめ、02 §2.1 のセクションの順と見出しコメントを守る。
   - 画面は `index.html` / `css.html` / `js.html` の3つに分け、include でつなぐ。
   - ファイルを増やさない（増やす必要があれば、ユーザーに提案して承認を得る）。
   - 完了報告では、「GAS エディタへ貼り替えが必要なファイル」を列挙する。
10. **画面のデザインは 05 §0 に従う**（K-44）。
    - 新しい部品が要るときは、まず参考アプリ `../02.ロッカーキー貸出管理(Gemini)/gas_app/css.html` に近い部品があるかを確かめ、その形とクラス名に合わせる。

## 3. 用語
| 用語 | 意味 |
|------|------|
| 届出 | 物品購入届1件（1物品） |
| 操作者 | 画面上部で選んだ社員（自己申告） |
| 入力者 | 届出を作った社員 |
| 指定承認者 | 届出で選んだ承認者（承認できるのはこの人だけ。K-01） |
| 仮設定 | システムが選んだ資材候補の最上位を、未確定のまま資材の列に入れた状態 |
| 確定 | 経理または管理者が資材を決めた状態（資材コード確定フラグが TRUE） |
| コード補完 | 手入力・指定なしの発注先・納入先に、経理がコードを設定すること |
| 開発環境／本番環境 | `物品購入届DB_開発`／`物品購入届DB` とそれぞれの紐づけスクリプト（K-42） |
