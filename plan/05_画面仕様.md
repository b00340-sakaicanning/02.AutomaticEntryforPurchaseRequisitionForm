- 版: v1.1（2026/10/31。デザインとコピペ反映の方針を追加）

## 0. デザイン方針（K-44）
- **参考アプリ**: `../02.ロッカーキー貸出管理(Gemini)/`（同じ `01.gemini` フォルダにある）
  - 原本: `gas_app/css.html`（CSS 変数は 5-49 行）、`gas_app/index.html`（ヘッダーは 20-64 行）、`gas_app/js.html`
- **目標**: 同じテイスト（色・フォント・角丸・影・部品の形・高さ）にそろえる。
- **実装のしかた**
  - 参考アプリの `css.html` の CSS 変数と、共通部品のクラス（ヘッダー・タブ・カード・テーブル・フォーム・ボタン・バッジ・モーダル・トースト・ローディング）を、このアプリの `css.html` に写して使う。
  - 参考アプリに固有の部品（キー選択カード `.key-card`、カテゴリバッジ `.category-badge` など）は写さない。
- **参考アプリの不備は写さない**
  - `--bg-main` が未定義のまま使われている（css.html:1095）
  - `.form-grid-2` が index.html:284 で使われているのに CSS に定義がない
  - Google Fonts の preconnect が2回書かれている

## 1. 共通（要 L174-178）

### 1.1 レイアウト
```
┌──────────────────────────────────────────────────────────────┐
│ 物品購入届            操作者: [▼ 雨○ ○○（品質保証課）] 🔓認証中(残り24分)[解除] │
├──────────────────────────────────────────────────────────────┤
│ [新規入力] [入力データ一覧] [承認済一覧] [システム反映済一覧] [マスタ管理]  │
├──────────────────────────────────────────────────────────────┤
│                    （タブごとの内容）                            │
└──────────────────────────────────────────────────────────────┘
```

**操作者**
- プルダウンで選ぶ。選択肢は社員マスタの有効な社員で、部ごとに `optgroup` でまとめ、氏名と課を表示する。
- 選んだ値は `localStorage`（キー `prOperatorId`）に保存し、次に開いたときの初期値にする（要 L55）。
- 操作者を変えたら、認証トークンを捨て、表示中のタブを読み直す。

**認証状態**
- 認証中は「🔓認証中（残りN分）」と「解除」ボタンを出す。
- 未認証のときは何も出さない。

**タブ**
- 「マスタ管理」は、操作者が管理者のときだけ出す（K-14）。
- 起動時は「新規入力」を表示する。

**表示環境**
- PC（Chrome・Edge）を主にする。
- 幅375pxでも崩れないこと（K-33）。区切りは §0.7 のとおり。
  - 一覧は横スクロールにする。
  - タブは横スクロールにする。

### 1.2 共通部品（見た目とクラスは §0.4）
| 部品 | 仕様 |
|------|------|
| ローディング | サーバーを呼んでいる間は、画面全体に半透明の覆いとスピナーを出し、ボタンを二重に押せないようにする（`toggleLoading`） |
| トースト | 成功・情報は3.5秒で消える。エラーは×で閉じるまで表示する（`showToast`） |
| 確認ダイアログ | 削除・承認・差し戻し・承認取消・CSV出力・反映済にする・承認済に戻すの前に出す（`showCustomConfirm`。危険な操作は `isDanger:true`） |
| 暗証番号ダイアログ | エラー `AUTH_REQUIRED` を受けたら出す。§2 |
| ステータスバッジ | §0.6 の地と文字の色で、ステータス名を表示する |
| 行の色 | §0.6 のとおり、左端の色帯と薄い地で色分けする |

### 1.3 サーバー呼び出し
- すべて `api(fnName, ...args)` を通す。
  - 中身は `google.script.run` を Promise で包んだもの。
  - `local_preview.html` では、モックに差し替わる（§9）。
- 第1引数には、必ず `ctx = {operatorId, token}` を渡す。
- 戻り値が `{ok:false}` のときの処理は、エラーコードで分ける。

| エラーコード | 画面の動き |
|-------------|-----------|
| `AUTH_REQUIRED` | 暗証番号ダイアログを出し、認証できたら同じ呼び出しをやり直す |
| `VALIDATION` | 項目ごとのメッセージを、入力欄の下に赤字で出す |
| `CONFLICT` | トーストを出し、「再読み込み」ボタンで一覧または届出を読み直す |
| それ以外 | エラーのトーストを出す |

## 2. 暗証番号ダイアログ（K-13）
```
┌ 暗証番号の入力 ─────────────────┐
│ 承認者・管理者・経理として操作するには   │
│ 暗証番号が必要です。                    │
│ 操作者: 雨○ ○○                        │
│ 暗証番号: [●●●●●●]                     │
│                    [キャンセル] [認証]  │
└──────────────────────────────────┘
```
- 入力欄は `type="password"`、`inputmode="numeric"`、`autocomplete="off"` にする。
- 認証に成功したら、トークンと期限を `sessionStorage`（キー `prAuth`。中身は `{operatorId, token, expiresAt}`）に保存し、元の操作をやり直す。
- 失敗・ロック・未発行のときは、サーバーが返したメッセージをダイアログの中に出す。

### 3.2 項目の動き（04 §4.1 と対応）
| 項目 | 動き |
|------|------|
| 部門 | 初期値は、操作者の既定部署コード。変えたら、承認者の候補を読み直す |
| 種別 | 有効な種別を表示順で出す |
| 入力者 | 新規なら操作者の氏名、修正なら届出の入力者名を表示する。変更できない |
| 承認者 | 04 §4.3 の候補を出す。候補が1人なら自動で設定し、2人以上なら優先順が最小の人を初期値にする。候補が0人なら赤字で K-12 のメッセージを出し、「承認依頼」を非活性にする |
| 発注先・納入先 | ラジオボタンで区分を選ぶ。「マスタから選ぶ」は検索付きプルダウン（§3.3）、「手入力」はテキスト（100文字）、「指定なし」は入力欄を隠す |
| 数量 | `inputmode="decimal"`。フォーカスが外れたら、全角を半角に直す |
| 納品日 | `type="date"`。送るときに `yyyy/MM/dd` に直す |
| 添付 | 選んだ時点で、拡張子とサイズを確認する。表示はファイル名と「表示」「削除」。新規の場合は保存後にアップロードする（04 §9） |

### 3.3 検索付きプルダウン（発注先・納入先）
- テキストを入れると、名称・カナ・略称・コードで部分一致した候補を、最大30件表示する。
  - 比べるときは、全角・半角とひらがな・カタカナの違いを無視する。
- 候補の表示は「名称（略称）／コード-枝番」。
- 選んだら、コードと枝番を隠し項目に入れる。
- 発注先の候補は、`表示=TRUE` の発注先だけにする。初期データとして受け取り、画面の中で絞り込む。

- 「クリア」は、確認してから入力内容を初期値に戻す（新規のときだけ）。

### 4.2 行ボタン（常に同じ並びで表示し、使えないボタンは非活性にして、理由をツールチップで出す）
| ボタン | 有効になる条件 | 押したときの動き |
|--------|---------------|-----------------|
| 詳細 | 常に有効 | 詳細モーダル（§6） |
| 修正 | 04 §3.2 の「修正」が許可される | 新規入力タブを修正モードで開く |
| 承認依頼 | REQUEST が許可される（入力完了・差し戻し。一時保存のときは必須チェックで弾かれることがある） | 確認してから実行する |
| 承認依頼取消 | CANCEL_REQUEST が許可される | 確認してから実行する |
| 承認 | APPROVE が許可される | 確認してから実行する |
| 差し戻し | REJECT が許可される | 差し戻し理由の入力ダイアログ（必須、500文字）を出す |
| 削除 | DELETE が許可される | 確認してから実行する |

- 判定には、届出の状態と、操作者が持っている役割（入力者・指定承認者・管理者・経理）を使う。
- 暗証番号はボタンを押した後に求める。認証していないことを理由に、ボタンを非活性にはしない。

### 4.3 フィルタと並び替え
- **フィルタ**
  - ステータス（チェックボックスで複数選択）
  - 部門
  - 種別
  - 入力者
  - 承認者
  - 発注先（名称の部分一致）
  - 提出日（開始〜終了）
  - 購入物品名（キーワード）
- **クイックフィルタ**
  - 「自分の届出」: 入力者が操作者
  - 「自分が承認する承認依頼中」: 承認者が操作者で、ステータスが承認依頼中
- **実装**
  - 一覧のデータは、`getRequestList(ctx, {tab:'ALL'})` で全件取る。絞り込みと並び替えは画面の中で行う。
  - 並び順の初期値は、更新日時の新しい順。列見出しを押すと、昇順と降順が切り替わる。
  - 件数を「N件中M件を表示」と出す。

## 5. 承認済一覧タブ・システム反映済一覧タブ

### 5.1 承認済一覧（要 L197-206）
```
[全選択] [CSV出力] [反映済にする]  フィルタ: 部門[▼] 発注先[  ] 提出日[  ]〜[  ] CSV出力済[▼すべて/済/未]
┌─┬────────┬────┬──┬──────────┬──────────┬──────┬──┬──────────────┬──┬──┬────┬────────┐
│☐│届出ID   │提出日│部門│発注先(名/コード)│納入先(名/コード)│購入物品名│型番│資材コード(候補/確定)│入数│数量│納期│CSV出力済│
└─┴────────┴────┴──┴──────────┴──────────┴──────┴──┴──────────────┴──┴──┴────┴────────┘
```

**列の表示**
- 発注先・納入先: 名称とコードを2段で表示する。コードが空なら、黄色で「コード未設定」と出す。
- 資材コード
  - 確定済みなら、コードと名称を表示する。
  - 仮設定なら、「候補: コード 名称」をグレーで出し、黄色で「資材未確定」と出す。
  - 資材なしで確定したなら、「資材なし（確定）」と出す。
- 納期: 出力される値を表示する（納品日が無ければ、月末の補完値に「（補完）」を付ける）。
- CSV出力済
  - 出力済みなら、日時と回数を表示する。
  - 要再出力なら、赤で「要再出力」と出す（04 §6.5）。

**経理・管理者の行操作**（それ以外の人には非活性）
| ボタン | 動き |
|--------|------|
| 資材 | 資材の選択ダイアログ（§6.3）を出す |
| コード | 発注先・納入先コードの補完ダイアログ（§6.4）を出す |
| 詳細 | 詳細モーダル |

**上部のボタン**
| ボタン | 動き |
|--------|------|
| 全選択 | 表示中の行をすべて選ぶ／外す |
| CSV出力 | 選んだ行を出力する。警告（コード未設定・資材未確定）がある行の件数を確認ダイアログで出し、「出力する」を押したら実行する。成功したら、ファイルを自動でダウンロードし、一覧を更新する |
| 反映済にする | 選んだ行のうち、CSV出力済でない行があれば、エラーにして件数を出す。確認してから実行する |

- フィルタ: 部門、発注先、提出日の期間、CSV出力済（すべて／済／未）

## 6. 詳細モーダルとダイアログ

### 6.1 詳細モーダル（要 L216）
- **全項目**: 入力項目、システム項目（提出日、資材、CSV出力、反映）を表示する。
- **添付**
  - 枠ごとにファイル名と「表示」「ダウンロード」を出す（K-41）。
  - 表示: PDF と画像は新しいタブで開く（Base64 から Blob URL を作る）。
  - Excel はダウンロードだけにする。
- **差し戻し理由**: 値があれば表示する。
- **ステータス履歴**: 操作ログを日時の昇順で表として出す（日時、操作、操作者、変更前→変更後、詳細）。
- 下部に「修正」ボタン（権限がある場合のみ有効）と「閉じる」ボタンを置く。

### 6.2 差し戻し理由ダイアログ
- 複数行テキストで、必須・500文字。
- 「差し戻す」で実行する。

### 6.4 コード補完ダイアログ（経理・管理者。K-39）

## 9. local_preview.html（K-43。CLAUDE.md の「プロジェクト固有のルール」）
- **目的**: GAS にデプロイしなくても、ブラウザで画面の見た目と動きを確認できるようにする。
- **作り方**: `node tools/build_local_preview.js` で、プロジェクト直下に `local_preview.html` を生成する。
  1. `gas_app/index.html` を読み、`<?!= include('css'); ?>` と `<?!= include('js'); ?>` を、それぞれのファイルの中身に置き換える。
  2. `js.html` の直前に `tools/preview_mock.js` を `<script>` として埋め込む。
     - `preview_mock.js` は、`window.google.script.run` の代わりと、モックデータを持つ。
     - モックデータは、社員5人（入力者・承認者・管理者・経理・兼務）、部署3、種別3、発注先10、納入先2、届出が各ステータス2件ずつ程度。
  3. テンプレートの式（`<?= ... ?>`）が他にあれば、モックの値に置き換える。
- **モックの規則**
  - サーバーの関数名と、戻り値の形（`{ok, data, error}`）を、06 の API仕様と同じにする。
  - 暗証番号はどの社員も `123456` で認証できるようにする。
  - モックのデータは `localStorage`（キー `prMock_v1`）に保存し、再読み込みしても操作の結果が残るようにする（参考アプリと同じ方式）。
  - 画面の上部に、固定のバナー `.preview-banner` を出す（参考アプリと同じ見た目。`#1e293b` の地に、`#0284c7` のバッジ「LOCAL MOCK PREVIEW」）。
    - バナーには「データ初期化」と「操作者の切替」のボタンを置く。
    - バナーは生成スクリプトが差し込む。本番の `index.html` には含めない。
- **更新の規則**: 画面の見た目や表示内容を変えたら、必ず作り直す。スクリーンショットは `screenshot/` に保存する。
