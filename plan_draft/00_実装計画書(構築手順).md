## 3. スプレッドシートの作成

### 3.1 スプレッドシートを新規作成する
- 名前: `物品購入届DB`（仮）
- 作成するシート:

| シート名 | 用途 |
|---------|------|
| 届出データ | 届出の本体（1行＝1届出） |
| 操作ログ | 操作の記録 |
| 部署マスタ | 部門の選択肢 |
| 種別マスタ | 種別の選択肢 |
| 社員マスタ | 操作者・入力者・承認者の選択肢 |
| 承認者対応表 | 部署ごとの承認者 |
| 権限マスタ | 管理者・経理担当と暗証番号ハッシュ |
| 発注先マスタ | 発注先の選択肢 |
| 納入先マスタ | 納入先の選択肢 |
| 資材マスタ | 資材コードの候補選定・入数 |
| 設定 | キーと値 |

### 3.2 届出データの列（案）
| 区分 | 列 |
|------|----|
| 基本 | 届出ID、ステータス、削除フラグ |
| 入力内容 | 部門コード、部門名、種別コード、種別名、入力者ID、入力者名、承認者ID、承認者名 |
| 発注先 | 発注先区分（マスタ／手入力／指定なし）、発注先コード、発注先枝番、発注先名 |
| 納入先 | 納入先区分、納入先コード、納入先枝番、納入先名 |
| 物品 | 購入物品名、型番、数量、単位・補足、理由、納品日 |
| 添付 | 添付1ファイルID、添付1ファイル名、添付2ファイルID、添付2ファイル名 |
| 資材 | 資材コード、資材枝番、資材サブ枝番、資材名、入数、資材コード確定フラグ |
| 日時 | 作成日時、作成者、更新日時、更新者、提出日、承認依頼日時、承認日時、承認実施者、差し戻し日時、差し戻し理由 |
| CSV・反映 | CSV出力日時、CSV出力者、CSV出力回数、反映済日時、反映操作者 |

- コード列（発注先コード、納入先コード、資材コード）は、書式を「書式なしテキスト」にして先頭の0を残す。

### 3.3 設定シートの初期値（案）
| キー | 初期値 |
|------|--------|
| ATTACHMENT_FOLDER_ID | 添付書類フォルダのID |
| BACKUP_FOLDER_ID | バックアップフォルダのID |
| PIN_SESSION_MINUTES | 30 |
| CSV_COLUMNS | 発注先コード,納入先コード,資材コード,入数,数量,納期 |
| CSV_HEADER | TRUE |
| CSV_DATE_FORMAT | yyyyMMdd |
| CSV_CHARSET | Shift_JIS |
| NOTIFY_ENABLED | FALSE |
| STATUS_COLORS | 各ステータスの色（JSON） |
| ATTACHMENT_MAX_MB | 10 |

## 4. Googleドライブの準備
1. オーナーアカウントのドライブに `物品購入届` フォルダを作る。
2. その中に `添付書類`、`マスタ取込`、`バックアップ` の各フォルダを作る。
3. 各フォルダのIDを設定シートに登録する。
4. フォルダは誰とも共有しない（添付書類はアプリ経由で表示する）。

---

## 5. マスタの初回取込

| 順 | マスタ | 作業 |
|----|--------|------|
| 1 | 資材マスタ | `資材マスター.csv`（CP932）を取り込む。全58列のうち、要件定義「9. マスタ定義」の列だけを残す |
| 2 | 部署マスタ | 資材マスタの DepartmentCode / DepartmentName（21種類）から作る。対象部署を有効にする |
| 3 | 種別マスタ | 資材マスタの MaterialType / 資材種別名（73種類）から作る。対象種別を有効にする |
| 4 | 発注先マスタ | `取引先マスター.csv`（CP932、セル内改行あり）を取り込む。仮条件（科目名2が買掛金・未払金）で表示対象にする |
| 5 | 納入先マスタ | 取引先マスタから自社拠点（倉庫など）のコードを選んで登録する |
| 6 | 社員マスタ | `365User.csv`（UTF-8）を取り込む。社員IDはメールアドレス。課名（部署2）を部署マスタの部署名と照合して既定部署コードを入れる。accountEnabled=FALSE は無効にする |
| 7 | 承認者対応表 | 社員マスタの課長・課長代理から初期案を作り、管理者が確認・修正する（品質保証課・総務課・営業課は要調整） |
| 8 | 権限マスタ | 管理者・経理担当を登録し、暗証番号を発行する |

- 取込は管理メニュー（スプレッドシートのカスタムメニュー、後で画面化）から行う。CSVを `マスタ取込` フォルダに置き、取込を実行する。
- 取込時は Shift_JIS で読み込む。コード列は文字列のまま保存する。
- `資材単価結合マスタ.xlsx` はコードの先頭の0が消えているため使わない。`商品マスター`・`ブランドマスター` は対象外。

## 6. GASプロジェクトの作成
1. スプレッドシートから「拡張機能 > Apps Script」でコンテナバインドのプロジェクトを作る（またはスタンドアロンで作り、スプレッドシートIDを設定する）。
2. 開発端末で `gas_app/` に移動し、`clasp login`、`clasp clone <スクリプトID>` を行う。
3. `appsscript.json` に、タイムゾーン `Asia/Tokyo`、ウェブアプリの設定（実行ユーザー: 自分、アクセス: 全員）を書く。
4. 以後は `clasp push` でコードを反映する。

## 7. 段階的な実装

各フェーズの完了条件を満たしてから次へ進む。画面に関わる変更をしたら `local_preview.html` も更新する。

| フェーズ | 内容 | 完了条件 |
|---------|------|----------|
| 1. データ層 | シートの読み書き、届出IDの採番、LockService、楽観ロック、操作ログ | 関数単体でデータを登録・更新・取得できる |
| 2. マスタ取込 | CSV取込（CP932・セル内改行対応）、マスタのキャッシュ | 6種類のマスタが正しい件数・先頭の0付きで入る |
| 3. 画面の骨組み | doGet、タブ切り替え、操作者の選択、暗証番号の認証 | 4タブが切り替わり、操作者を選べる |
| 4. 新規入力画面 | 入力項目、発注先・納入先の3通りの入力、承認者の絞り込み、一時保存・入力完了 | 一時保存と入力完了で保存でき、必須チェックが働く |
| 5. 入力データ一覧 | 一覧表示、色分け、フィルタ、行ごとのボタン、修正モード | ステータスと操作者に応じてボタンが切り替わる |
| 6. 承認フロー | 承認依頼、承認依頼取消、承認、差し戻し（理由必須）、承認取消、権限チェック | 要件定義の遷移表と権限マトリクスどおりに動く |
| 7. 添付書類 | アップロード、差し替え、プレビュー・ダウンロード | 一時保存の段階から添付でき、詳細画面で見られる |
| 8. 資材コード | 候補選定（優先順4段階）、経理担当の確定・変更、資材マスタ検索 | 承認時に候補が仮設定され、経理担当が確定できる |
| 9. 承認済一覧とCSV | 複数選択、警告表示、コード補完、CSV出力（Shift_JIS）、出力記録、反映済にする | 出力したCSVが仮仕様どおりで、納期の月末補完が正しい |
| 10. 反映済一覧 | 閲覧、再出力、承認済に戻す（管理者） | 承認済一覧に反映済のデータが出ない |
| 11. 通知の拡張点 | 通知関数の用意（NOTIFY_ENABLED=FALSE で何もしない） | 設定を TRUE にすると送信処理が呼ばれる |
| 12. 運用機能 | 月次バックアップのトリガー、マスタ管理画面 | バックアップが作られる |

## 8. テスト

### 8.1 テスト用データ
- 社員マスタにテスト用の入力者・承認者・管理者・経理担当を用意し、暗証番号を設定する。

### 8.2 テスト観点
| 区分 | 確認内容 |
|------|----------|
| 入力 | 必須チェック、文字数、日付形式、数量の数値チェック、発注先・納入先の3通りの入力 |
| ステータス遷移 | 遷移表の全パス（承認依頼取消→入力完了、差し戻し→再依頼、承認取消→承認依頼中、反映済→承認済に戻す） |
| 権限 | 権限マトリクスの全セル。暗証番号の誤り・期限切れ。自分の届出を自分で承認できないこと |
| 提出日 | 最初の承認依頼日が入り、再依頼で変わらないこと |
| CSV | 列順、ヘッダ、Shift_JIS、CRLF、先頭の0、空白になるケース（手入力・指定なし・資材未確定）、納期の月末補完（月末日・うるう年の2月を含む） |
| 資材コード | 優先順1〜4それぞれで候補が出ること、無効資材が除かれること |
| 添付 | サイズ上限、形式制限、差し替え時に旧ファイルがゴミ箱へ移ること |
| 同時操作 | 2つのブラウザで同じ届出を更新し、後から保存した側がエラーになること |
| 表示 | 一覧の色分け、フィルタの組み合わせ、承認済一覧に反映済が出ないこと |

- 画面確認のスクリーンショットは `screenshot/` に採取し、作業完了時に `screenshot/YYYYMMDDhhmm_変更内容/` へ移す。

## 9. デプロイ
1. `clasp push` の後、Apps Scriptエディタで「デプロイ > 新しいデプロイ > ウェブアプリ」を選ぶ。
2. 設定: 次のユーザーとして実行「自分」、アクセスできるユーザー「全員」。
3. 初回は権限の承認（スプレッドシート、ドライブ、外部へのリクエストなし）を行う。
4. 発行されたURLを社内でのみ配布する。
5. 更新時は「デプロイを管理」から同じデプロイの版を上げ、URLを変えない。
